# PAChecker Phase 6 후속 AI 기능 검토

## 공통 원칙

- Phase 6 항목은 현재 계획상 구현이 아닌 도입 검토 범위입니다.
- 모든 AI 결과는 초안이며 사용자 확인·수정·확정 전 핵심 데이터에 반영하지 않습니다.
- 기존 CRUD, 날짜, 알림은 후속 AI 기능과 독립적으로 동작합니다.
- 서버 전용 CLIProxyAPI 어댑터와 구조화 검증 패턴을 재사용합니다.
- 개인용 프로젝트에 필요한 최소 데이터와 화면만 추가합니다.

## 1. 수행평가 준비 작업 자동 분해

### 권장안

확정된 수행평가의 제목, 설명, 준비물, 평가일, `extra_fields`를 입력으로 받아 준비 작업 목록 초안을 생성합니다. 원본 이미지 재분석은 사용자가 별도로 요청할 때만 수행합니다.

구조화 출력 후보:

```json
{
  "tasks": [
    {
      "title": "발표 자료 개요 작성",
      "description": "핵심 주장과 근거를 정리",
      "estimatedMinutes": 40,
      "dependencies": [],
      "sourceFields": ["description", "extra_fields.평가 기준"]
    }
  ],
  "warnings": []
}
```

검증 규칙:

- 작업 제목은 비어 있지 않아야 합니다.
- 예상 시간은 양의 정수와 상한을 적용합니다.
- 의존성은 같은 초안의 작업만 참조합니다.
- 수행평가 핵심 필드를 작업 데이터로 덮어쓰지 않습니다.

사용자 흐름은 생성 요청, 작업 초안 표시, 추가·삭제·순서·시간 수정, 사용자 확정 저장 순서로 구성합니다.

실제 구현 시 별도 `preparation_plan_drafts`와 `preparation_tasks` 테이블을 권장합니다. 계획 초안에는 수행평가 스냅샷, 선호 설정, 제안 작업, 일정, 상태와 오류를 두고, 확정 작업에는 `assessment_id`, 제목, 설명, 예상 시간, 권장일, 상태, 순서, 출처를 둡니다. 수행평가가 초안 생성 후 변경되면 스냅샷을 비교해 `stale`로 표시합니다. 별도 프로젝트·보드·협업 모델은 추가하지 않습니다.

## 2. 준비 작업별 권장 일정 생성

### 권장안

수행평가 날짜에서 역산하는 결정론적 스케줄러를 우선하고 AI는 작업 분해와 예상 시간 제안에만 사용합니다.

입력 후보:

- 수행평가 날짜
- 확정된 준비 작업과 의존성
- 작업별 예상 시간
- 사용 가능한 요일과 하루 최대 준비 시간
- 시작 가능 날짜

규칙:

1. 의존 작업은 후속 작업보다 앞에 배치합니다.
2. 최종 검토·제출 준비 여유일을 확보합니다.
3. 기한 경과 날짜에 작업을 배치하지 않습니다.
4. 하루 최대 시간을 넘기면 경고합니다.
5. 수행평가 날짜 자체를 자동 변경하지 않습니다.

결과는 일정 초안으로 표시하고 사용자가 수정·확정한 뒤 저장합니다. 일정이 성립하지 않으면 임의로 압축하지 않고 충돌 이유와 미배치 작업을 보여줍니다. AI가 날짜까지 직접 생성하는 방식은 재현성과 설명 가능성이 낮아 초기 권장안에서 제외합니다.

## 3. 누락 또는 모순 탐지

### 권장안

결정론 검사를 먼저 실행하고 AI 의미 검사를 선택적으로 추가합니다.

결정론 검사:

- 제목·과목·날짜 누락 또는 잘못된 달력 날짜
- 지난 날짜인데 진행 중인 상태
- 본문에는 준비물이 있으나 준비물 필드가 비어 있는 경우
- `extra_fields`에 핵심 필드 이름이 중복된 경우
- 원본은 연결되었으나 분석 결과가 없는 경우

AI 보조 검사:

- 설명과 평가 기준의 의미 충돌
- 본문 날짜와 핵심 날짜 불일치
- 제출 형식·분량의 상충
- 준비물·제출물의 잠재적 누락

탐지 결과는 `source`, `severity`, `code`, `fieldPaths`, `message`, `evidence`, 선택적 `suggestion`을 가진 이슈 목록으로 표현합니다. 탐지 메타데이터는 사용자 데이터인 `extra_fields`에 넣지 않습니다. AI 검사는 검토 제안으로 표시하며 필드를 자동 수정하지 않습니다. 실제 달력 오류 같은 결정론적 오류만 저장 전 검증 대상으로 둡니다.

현재 이미지 분석 스키마는 제목과 날짜를 필수로 요구하므로 누락은 실패 초안으로 표현됩니다. 후속 탐지 기능에서는 누락·모호성을 정상 결과로 표현하는 별도 제안 스키마를 사용하고, 최종 확정 단계에서만 필수 핵심 필드를 강제합니다. 확정 API는 일부 변경값이 아닌 검토된 전체 스냅샷을 제출해 기존 `extra_fields` 손실을 방지합니다.

## 4. 자연어 직접 입력

### 권장안

“9월 25일 국어 발표, 대본과 PPT 준비” 같은 텍스트를 구조화 초안으로 변환하고 Phase 4의 검토 UI와 확정 저장 흐름을 재사용합니다.

흐름:

1. 자연어 입력
2. 서버에서 CLIProxyAPI 텍스트 구조화 요청
3. 고정 핵심 필드와 `extra_fields` 스키마 검증
4. 기존 AI 초안 화면에서 과목·날짜·준비물 확인
5. 사용자 확정 후 수행평가 생성

“다음 주 금요일” 같은 상대 날짜에는 요청 시점의 로컬 날짜와 시간대를 전달합니다. 연도·시간·학기 등이 모호하면 추측 확정하지 않고 경고합니다. 여러 날짜가 있으면 평가일과 제출일 후보를 분리해 사용자 선택 대상으로 둡니다.

### 초기 권장안

분석 결과를 영속화하지 않고 기존 직접 등록 폼에 안전하게 채워 넣습니다. 최종 저장은 기존 수행평가 생성 API와 알림 저장 흐름을 그대로 사용합니다. 이 방식은 DB 마이그레이션이 없고 AI 장애와 CRUD를 분리하기 쉽습니다.

### 대안

페이지 이탈 후 자연어 초안을 다시 여는 요구가 확인되면 `ai_drafts`에 `source_type`, 선택적 `source_image_id`, 선택적 `source_text`를 추가해 출처를 일반화합니다. 이미지 전용 구조를 그대로 강제하거나 별도 텍스트 초안 시스템을 복제하는 방식은 권장하지 않습니다.

## 권장 구현 순서

1. 결정론적 누락·모순 검사
2. 준비 작업 수동 CRUD와 데이터 모델
3. 결정론적 역산 일정 생성
4. 준비 계획 초안 생명주기와 stale 탐지
5. AI 준비 작업 분해 초안
6. 자연어 직접 입력의 임시 폼 채우기
7. AI 의미 기반 모순 탐지
8. 실제 재개 요구가 확인된 경우에만 공통 초안 출처 일반화

## 도입 조건

- MariaDB 마이그레이션과 백업 절차 확인
- 실제 CLIProxyAPI 구조화 응답 smoke test
- Phase 2-4 핵심 흐름의 PC/iPhone 실기기 검증
- 기능별 구조화 스키마, 실패 처리, 사용자 확정 화면 정의
- 기존 CRUD가 AI 장애와 독립적으로 유지되는 회귀 검증

## 비목표

- 사용자 확인 없는 일정 또는 수행평가 자동 생성
- 학교 공식 시스템 자동 연동
- 여러 사용자의 작업 배정과 협업
- AI가 생성한 일정의 백그라운드 자동 변경
- 초기 버전의 복잡한 캘린더 최적화
